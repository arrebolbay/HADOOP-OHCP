01技术栈：每一层都有明确分工

不是堆技术，而是让“存储—计算—服务—智能”各司其职

Hadoop 3.3.6

HDFS + YARN

按月分片写入 HDFS，原始分片留档、清洗分片供计算； 计算与存储分离，预留横向扩容接口。

Hive 3.1.3

ODS → DWD → DWS → ADS

SQL 完成类型转换、量程过滤、城市日均与年月聚合； 口径与 Python 侧一致。

MapReduce Streaming

独立再算一遍

Python 写 map/reduce 统计城市 PM2.5 均值， 与 Hive 结果逐城市对账。

MySQL 8.0

结果库

3 张事实表 + 维表 + 视图 + 存储过程 + 定时事件； Agent 与前端毫秒级查询。

Python 3.10

pandas · matplotlib · unittest

分片清洗引擎、国标判定、图表与 37 项自动化测试； 全部纯函数、可单测。

ReAct Agent

8 个工具 + 双模规划

LLM 只做任务拆解；无 Key/断网自动切规则规划器； Web 端零依赖（http.server）。

关键约束：大模型不参与任何数值计算，所有统计与判定都在本地真实数据上由工具完成， 结果可复算、可对账。

0:15–0:55

我们的技术栈分四层：Hadoop 负责存储，Hive 和 MapReduce 负责计算，MySQL 做结果服务， Python 负责数据引擎和 Agent。

特别说明两点：第一，Hive 和 MapReduce 会把同一个指标各算一遍，用来对账； 第二，大模型只做任务规划，所有数字来自本地工具，避免编造结果。

03优点：结果可信、演示可靠

相比“能跑通”的同类方案，我们多做了一步：让结果可证明

1

真实数据、可复核

国家城市空气质量实时发布平台公开数据；分片清洗前后行数、缺失、越界、填充量全部落盘。

2

三方对账

Hive、MapReduce、pandas 对同一指标各算一遍；偏差写入 hive_vs_pandas.json、mapreduce_vs_hive.json。

3

演示不翻车

LLM 规划 + 规则兜底双模；无网络、无 Key 依然能完整跑通 3 个官方示例。

4

结果有护栏

5 类校验：非空、物理范围、国标一致性、加权独立复算、MySQL 跨引擎对账； 不通过会明确标红。

5

业务化思政

超标研判自然带出国标限值科普与 1~2 行生态感悟，重污染自动附污染物健康科普卡片。

6

零依赖 Web 交付

标准库 http.server 同时托管前端与 API，一条命令启动，现场少一个故障点。

1:15–1:25

优点可以概括成两句话：第一，真实数据和三方对账让结果可信； 第二，双模规划和结果校验让现场演示可靠，断网也能跑。

04局限与应对：不回避边界

一小时比赛做的是可交付的最小闭环，而不是“无所不能”

局限说明应对 / 下一步
单机伪分布式 HDFS/YARN 部署在同一台机器，不是真实多节点集群。 分片接口与 HDFS 路径已保留，增加节点即可横向扩展，无需改业务代码。
指标范围有限 当前覆盖 6 项常规污染物 + AQI，未包含更多特征污染物。 配置表驱动，新增指标只需扩展字段映射与国标限值表。
大模型依赖 自然语言理解上限受模型能力影响；API 可能限流或断网。 只用于任务拆解；超时 8 秒自动切规则规划器，计算永不离线。
批处理时效 数据更新需要重跑分片与聚合，不是实时流。 分片命名与读取接口已预留，可接 Flink/Spark Streaming 增量计算。
取舍逻辑： 一小时里优先保证“真实数据 + 正确口径 + 可复现演示”； 扩展性通过接口与配置预留，而不是堆功能。

1:25–1:30

局限主要有四个：单机伪分布式、指标范围、模型依赖和批处理时效。 我们的应对分别是：分片扩容、配置扩展、规则兜底、预留流式接口。
