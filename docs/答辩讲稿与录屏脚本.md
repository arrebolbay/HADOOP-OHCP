# 答辩讲稿与录屏脚本（HTML 演示）

> 答辩形式：**HTML 幻灯片 1.5 分钟 + 录屏演示 3.5 分钟**。
> HTML 演示页：`docs/答辩演示.html`（双击用浏览器打开；`←/→` 翻页，`N` 看讲稿，`F` 全屏）。
> 产品演示：`./start.sh` 一键启动前后端，浏览器打开 `http://127.0.0.1:8000`。

---

## 一、1.5 分钟技术栈介绍（照读即可，约 380 字）

### 0:00–0:15 封面（第 1 页）
> 各位老师好，我们做的是**空气质量时序分析 Agent**。用户只需要一句中文提问，
> 系统就会自动完成数据清洗、聚合统计、国标超标研判、画图和结论输出。
> 技术上使用 Hadoop、Hive、MapReduce、MySQL 和 Python。

### 0:15–0:55 技术栈（第 2 页）
> 技术栈分四层：**Hadoop** 负责分布式存储，分片写入 HDFS；
> **Hive** 做 ODS 到 ADS 四层数仓，MapReduce 用 Python Streaming 把同一个指标独立再算一遍，
> 用来做双引擎对账；**MySQL** 存结果表，支撑 Agent 和前端查询；
> **Python** 负责清洗引擎、国标判定、绘图和 37 项测试；
> 最上层是 **ReAct Agent**，8 个工具、双模规划，Web 端用标准库实现，零额外依赖。
> 关键一点：**大模型只做任务拆解，不参与任何数值计算**，所有数字都能在本地复算。

### 0:55–1:15 架构（第 3 页）
> 链路是：真实数据 → 按月分片 → 清洗 → HDFS/Hive 三层建模 → MapReduce 对账 →
> MySQL → Agent → 图表和结论。读取、清洗、聚合全程按分片处理，全年 300 万行不会一次性进内存；
> 三个引擎的结果会互相对账，保证不是"跑通一次"的偶然结果。

### 1:15–1:30 优点与局限（第 4、5 页，快速带过）
> 优点可以概括为：真实数据可复核、三方对账、断网可演示、结果有校验护栏、思政自然融入。
> 局限也明确：单机伪分布式、指标范围、模型依赖、批处理时效；
> 我们分别用分片扩容、配置扩展、规则兜底、预留流式接口来应对。

### 1:30–1:35 过渡（第 6 页）
> 这些数字都能在 `output/` 目录找到对应文件，测试和对账都可以现场重跑。
> 下面进入三分半的录屏演示。

## 二、3.5 分钟录屏脚本（边操作边讲）

### 录屏前 1 分钟检查
1. 运行 `./start.sh`，确认页面能打开、顶部三个胶囊为绿色；
2. 浏览器缩放 **125%**，全屏（F11），关闭通知与其他窗口；
3. 先点一次「示例 1」预热缓存（结果出现后点「清空多轮记忆」并刷新，正式录屏）；
4. 若现场无网络/无 Key：在左侧「运行设置」选 **规则规划器**，讲解词不变。

### 0:00–0:20 开场
- 操作：停留在首页，鼠标指向顶部「数据 12 个分片 / MySQL / 规划器」状态胶囊。
- 口播：这是完整产品界面，左侧是数据概览，右侧是自然语言分析区；
  后端 Agent、前端页面由一条命令同时启动。

### 0:20–1:10 示例 1：TOP5 + 月度曲线
- 操作：点左侧「示例 1」或欢迎卡片。
- 口播：Agent 先规划，再依次调用读取、清洗、聚合、国标判定、绘图、校验等工具。
- 操作：结果出现后，先指 **TOP5 统计结果**，再指 **GB 3095 年均限值 35** 的判定行。
- 操作：展开「ReAct 决策轨迹」，快速下滑展示 8 个步骤与 Observation。
- 操作：指折线图与右侧「校验 5/5」徽章。
- 口播：所有数字来自本地真实分片，工具返回什么，页面就展示什么。

### 1:10–2:10 多轮追问：PM10
- 操作：点左侧「追问：多轮记忆」。
- 口播：这次没有输入城市名，Agent 从上一轮记忆里自动带入 TOP5 城市，换成 PM10 继续分析。
- 操作：指结果头部「记忆：商丘、菏泽…」标签和新的折线图。
- 口播：这就是题目创新点里的多轮对话记忆，演示时不用重复输入。

### 2:10–3:10 省份占比 + 突变告警
- 操作：点「示例 2：省份超标占比」。
- 口播：换成地域维度，统计各省 PM2.5 超标城市-天数与占比，饼图按全国超标总量归一。
- 操作：指饼图和「省内超标率」数字。
- 操作：点「告警：突变检测」。
- 口播：这个工具检测月度环比突变，只有变化率和绝对变化同时超过阈值才告警，避免噪声误报。

### 3:10–3:30 收尾：概览与证据
- 操作：滚回顶部，鼠标依次指 **361 天 / 342 城 / 12 分片 / 37 项测试**。
- 口播：数据规模、分片数、测试数都能复核；Hive、MapReduce、pandas 三方对账结果在 `output/` 里。
- 收尾：我们不仅让 Agent 跑通，还让每一个数字可对账、每一次演示不翻车，谢谢老师。

## 三、常见提问速答（每个 20 秒内）

| 问题 | 回答要点 |
| --- | --- |
| 为什么用了 Hadoop 却还是单机？ | 教学/比赛环境是伪分布式；分片路径、HDFS 目录、MapReduce 作业都按集群方式写，增加节点即可扩展，不需要改业务代码。 |
| 大模型会不会编数据？ | 不会。LLM 只输出"调用哪个工具、什么参数"的 JSON；统计、判定、绘图全部由本地工具执行，且校验工具会复算与对账。 |
| 没有网络/没有 Key 怎么办？ | 双模规划器：`auto` 模式 8 秒超时或报错自动降级到规则规划器；页面左侧可手动选择"规则规划器"。 |
| 怎么保证国标判定正确？ | 限值集中在 `core/gb3095.py`，边界值（35.0 达标 / 35.1 超标）有单元测试；Hive/图表/报告引用同一套限值。 |
| 与同侪方案最大的差异？ | 三方对账 + 双模规划 + 5 类结果校验 + 分片工程；不仅跑通，还能证明结果正确、演示稳定。 |
| 数据是真实的吗？ | 国家城市空气质量实时发布平台公开数据，361 天、342 城；源站有 5 天缺档，已在数据说明中如实注明。 |

## 四、HTML 演示页操作说明

| 按键 | 作用 |
| --- | --- |
| `→` / 空格 / PageDown | 下一页 |
| `←` / PageUp | 上一页 |
| `N` | 显示/隐藏讲稿（含时间点） |
| `F` | 全屏 |
| `Home` / `End` | 第一页 / 最后一页 |

- 页面地址：`docs/答辩演示.html`（零依赖，不联网也能打开）；
- 打印为 PDF：浏览器 `Ctrl+P` 可直接导出 7 页讲义；
- 讲稿内容与每一页绑定，按 `N` 即可看到对应时间段的逐字稿。
