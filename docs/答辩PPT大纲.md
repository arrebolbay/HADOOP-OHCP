## 第 3 页｜架构方案：一张图讲清系统（1.5 分钟）
**对应维度 2：Harness 过程与系统架构合理性（20%）**

```
真实数据（2024 全国城市空气质量）
  → 分片（按月 chunk）
  → 清洗 DWD（Python + Hive 双实现，口径一致）
  → HDFS / Hive ODS→DWD→DWS→ADS
  → MapReduce 独立计算（双引擎对账）
  → MySQL 结果库（事实表/维表/视图/存储过程/事件）
  → ReAct Agent（LLM 规划 + 规则兜底）
  → 结论 + 图表 + 校验
```

- 分层解耦：`core`（纯计算，可单测） / `agent`（规划+工具） / `steps`（可复现流水线）
- 配置中心：`config.py` 一处改环境；`common.py` 统一 HDFS/Hive/MySQL 调用
- **Harness**：unittest 37 项；fixture 使用真实数据子集；E2E 覆盖完整工具链；
  三方对账（Hive / MapReduce / pandas）作为集成测试

## 第 7 页｜系统亮点：与同侪解法对比（1.5 分钟）
**对应维度 6：系统亮点（20%）**

| 同侪常见做法 | 本方案 |
| --- | --- |
| 单一引擎跑通，数字无法复核 | Hive + MapReduce + pandas **三方对账** |
| 强依赖大模型 API，现场断网即挂 | **双模 ReAct**：LLM 优先 + 规则兜底 |
| 出结果就交，口径容易错 | **validate 工具**：范围/国标/加权复算/MySQL 对账 |
| 一次性 load 全年数据 | **按月分片**读写、清洗、聚合 |
| 思政弹窗/大段说教 | 超标研判自然带出国标科普 + 1~2 行感悟 |
| 只能单轮问答 | **多轮记忆** + 突变告警 + 双模板 + 科普卡片 |

**一句话收尾**："我们不仅让 Agent 跑通，还让结果可证明、演示不翻车。"
