    技术栈与设计取舍

    1.5 分钟开场可直接照着这一页讲

    ① 全链路架构

    真实监测数据 → 按月分片 → 清洗 → HDFS / Hive 三层 → MapReduce 对账 → MySQL → ReAct Agent → Web 展示

    Hive、MapReduce、pandas 三方对账；统计口径统一由 core/gb3095.py 管理。

    ② 技术栈

    Hadoop 3.3.6Hive 3.1.3 MapReduce StreamingMySQL 8.0 Python 3.10pandas matplotlibReAct Agent http.server（零依赖 Web）

    ③ 优点

    • 真实可复核：真实公开监测数据，分片清洗前后数量可查
    • 三方对账：Hive / MapReduce / pandas 结果一致
    • 演示不翻车：双模规划，无网/无 Key 自动规则兜底
    • 结果有护栏：非空、范围、国标一致性、加权复算、MySQL 对账
    • 业务化思政：超标研判自然带出国标科普与 1~2 行生态感悟

    ④ 局限与应对

    • 单机伪分布式：非真实集群；分片接口保留，可平滑扩容
    • 指标范围：当前 6 项污染物 + AQI，可扩展更多指标
    • 大模型依赖：只用于任务拆解，可关闭并规则兜底
    • 批处理时效：数据更新需重跑分片，预留增量/流式接入位
    361 天真实数据 342 个城市 约 300 万 行记录 37 项自动化测试 GB 3095—2012 二级标准
